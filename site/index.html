    02Flight recorder

    Follow one request. Then break it.

    A store owner adds a product to their store. Ten hops later Inventory holds a stock level. Inject a failure, press play and watch which guarantee catches it.

    Inject a failure

    Order is not guaranteed

    The processor publishes a batch in parallel and consumers run concurrently, so events can arrive in any order. A read model fed by events carries the source version and applies it with UpsertIfNewerAsync, which drops a stale or duplicate event.

    Heavy work never runs in the request

    The endpoint stores the file, writes a job row and one queue message in a single transaction, and answers 202 with a job to poll. A consumer then works through the file in batches. Break something and send it.

    A copy can miss an event

    Inventory keeps a local copy of the product facts it needs, so a request never asks Products. Events keep the copy fresh, and a copy can still miss one. Rename a product, lose the event, then run the reconciliation job: it pages through Products and heals the row, guarded by the row's version.
